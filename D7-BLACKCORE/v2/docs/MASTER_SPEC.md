# D7 BLACKCORE 2.0 — MASTER SPEC (FROZEN CORE)

Status: **Accepted for 2.0 kernel build**

BLACKCORE is not a chatbot, optimizer, coding agent, or money bot. It is a **Personal Autonomous Operating System over Windows**: one master brain, specialist departments, persistent state, capability truth, evidence, learning and safe computer/internet execution.

## Product laws

1. NO CLAIM WITHOUT PROOF.
2. Do not break working systems.
3. Safe actions may be autonomous; destructive, financial, external-send/publish, credential/security-boundary and irreversible actions require approval.
4. Important changes must have an undo/compensation path.
5. Test before delivery; real-world end-to-end tests outrank mocked success.
6. Buyer before product; payment proof before revenue claims.
7. Code for deterministic execution; AI for reasoning.
8. Secrets never belong in prompts; scoped capabilities only.
9. No CAPTCHA bypass, ban evasion, unauthorized access or mass spam.
10. Capability truth over pretending.
11. Recover from last confirmed checkpoint.
12. Measure before/after when claiming improvement.

## User experience

The primary interface exposes only:
- **What do you want?**
- **What is BLACKCORE doing now?**
- **What needs approval?**
- **What is the verified result?**

Advanced internals are drill-down only. The design must be modern, responsive, lively, RTL/Arabic-first capable, and free from old Windows utility visual clutter. War Rooms/Studios appear contextually rather than as dozens of permanent pages.

## Definition of done for BLACKCORE features

A capability is not "done" because code exists. It requires: capability registered; risk policy defined; happy-path test; failure/recovery test; evidence; real target-machine verification when hardware/UI specific; regression coverage; and truthful capability status (VERIFIED/PARTIAL/UNTESTED/UNAVAILABLE).
